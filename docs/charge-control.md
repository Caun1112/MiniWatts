## 安装和权限

发布的 **MiniWatts-unsigned.ipa 是完全未签名的文件**，包括两个后台辅助程序。
项目仍要求 iOS 17+。常规 Apple ID 签名只能提供原有监测能力，不能赋予充电控制权限。
ChargeLimiter 原上游支持的巨魔版本范围到 iOS 17.0；本应用的最低版本是 17.0，
因此普通 TrollStore 与本应用的已知版本范围取交集。TrollStore Lite / rootless 越狱需另按其实际环境判断，不能因为本应用在新系统能启动就认为限充可用。

要使用控制功能，需支持这些权限的 TrollStore / 越狱安装环境，并给主程序、
`MiniWattsChargeDaemon`、`MiniWattsChargeHUD` 都应用发布附件
`ChargeControl.entitlements` 中的特权签名。安装工具必须支持嵌套辅助程序；
普通自签工具可能移除这些权限。未签名 IPA 本身不包含有效权限签名，不能保证
直接导入某个安装工具即可工作。Sileo 用户可直接安装内嵌权限和系统自启动服务的 rootless DEB。

有相应设备环境的用户可在 **解包后的副本** 中用 ldid 为这三个 Mach-O 添加
侧载特权签名，再重新打包交给兼容的安装工具。小组件仍用原来的权限配置。
这一步会生成新的签名文件，不应把它称为原始未签名发行物。

服务与上游 ChargeLimiter 使用独立端口和文件：

- `127.0.0.1:1231`，仅本机访问，不监听局域网。
- `/var/root/miniwatts-charge.conf`：设置。
- `/var/root/miniwatts-charge.db`：统计。
- `/var/root/miniwatts-charge.log`：滚动日志。

不要同时运行两个限充工具，它们会写入相同的硬件状态。控制默认关闭。
服务失联时，MiniWatts 会禁止原生控制并显示状态，不把 UI 开关作为硬件成功的证据。
服务启动、系统私有 API、通知、SBC 和系统悬浮窗仍需真机验证。
rootless DEB 的服务由 launchd 托管。开启“始终开启”会立即启用充电控制；服务异常退出后
launchd 会重新启动它，独立健康检查每 30 秒检查一次接口，并恢复无响应的系统服务。
服务恢复后立即读取电池并执行保存的充电策略，通知之外还有每 20 秒一次的后台检查，
不需要重新打开应用。实际恢复时间包括系统调度、启动和硬件读数延迟。
手机重启后，须先恢复越狱环境；未越狱状态下不能执行这些特权服务。
关闭“始终开启”保留当前充电控制状态；主动关闭自动充电控制会同时关闭“始终开启”。
TrollStore IPA 不包含系统守护任务，服务退出或设备重启后仍需重新打开应用。

“充电时自动限流”使用温控模拟，并非精确指定 mA 上限。启用自动充电控制后，
修改限流开关或等级会立即重新应用，停充或关闭限流时恢复默认温控等级。
温控锁定时以锁定等级为准。界面每 3 秒刷新实际电流，硬件响应与锁屏行为仍需真机验证。

## 快捷方式与 API

支持 `miniwatts:///charge`、`miniwatts:///nocharge`、`miniwatts:///enable`、
`miniwatts:///disable`；兼容 `cl:///charge/exit`、`cl:///nocharge/exit`、`cl:///exit`。
`exit` 在请求完成后关闭前台应用，后台服务继续运行。避免同时安装另一个注册 `cl` 的应用。

向 `http://127.0.0.1:1231/bridge` POST JSON，保留上游 API：
`get_conf`、`set_conf`、`reset_conf`、`get_bat_info`、`get_statistics`、
`set_charge_status`、`set_inflow_status`；新增 `get_diagnostics`。
例如 `{"api":"set_charge_status","flag":false}`。
返回 `status:0` 仅代表请求执行未报错，硬件读数仍可能延迟最多约 120 秒。
参数校验错误返回 -20。请求在主线程串行处理，避免统计数据库和配置并发修改。

## 真机验证及反馈

1. 先确认原有功率、温度、小组件正常；打开控制页检查是否连接到服务。
2. 保持自动控制关闭，在有电源时手动停充/恢复，观察电流和硬件充电状态。
3. 再开启自动控制，验证上下限、重新插拔、温度阈值与后台/锁屏行为。
   rootless 用户开启“始终开启”后关闭前台 App，终止服务或重启并恢复越狱，
   确认无需打开 MiniWatts 即能按保存阈值充停；主动关闭自动控制后确认不会重新启用。
4. 根据设备能力逐项测试高级选项、通知、悬浮窗、SBC；切勿把开关成功当成硬件成功。
5. 出现问题后到「Bug 日志」填写时间和重现步骤，生成并分享 JSON。
   报告含提交版本、环境、传感器快照、本机滚动日志、服务日志及请求返回码。
   常见序列号/设备标识字段会被过滤；请在分享前检查自己填写的问题描述。
6. 若闪退，同时提供系统「分析数据」中的 MiniWatts / MiniWattsChargeDaemon `.ips`；
   普通应用无权自动读取系统崩溃报告。

所有 IPA 均由 GitHub Actions 编译。源码包含完整依赖，不需要第三方预编译框架、
Theos 或私有 SDK。GitHub Release 提供未签名 IPA、权限配置和对应源码。

## 相对上游的代码修正说明

| 修改 | 原因与行为变化 |
|---|---|
| 独立端口、配置、日志和数据库 | 避免覆盖单独安装的 ChargeLimiter 数据；不代表两个限充服务可以同时启用。 |
| 默认简体中文 | 前端、后台通知首次默认中文；明确选择的语言保持不变。 |
| HTTP 参数和统计表名校验 | 拒绝错误类型、交叉阈值、越界温度及任意表名，避免错误配置和 SQL 拼接风险。 |
| 请求串行处理 | UI 请求与电池事件共用主运行循环，防止配置和 SQLite 并发访问。 |
| 快充恢复原状态 | 保存进入快充前的飞行模式、Wi-Fi、蓝牙、低电量与亮度；重复触发不覆盖快照；关闭快充、停用控制、重置和退出时恢复。原版会直接切成固定状态。 |
| 生效与回读 | 设置自动策略后立即重新评估；原生界面等待服务确认后更新，硬件状态由读数显示。保留上游插电/边缘触发和极低电量优先顺序。 |
| 缺失传感器处理 | 必须的电量、充电状态或启用温控后的温度缺失时跳过自动控制，不再把缺失值当作 0。 |
| SDK 兼容 | 动态查询不可直接编译的私有 spawn 接口；补齐 CoreGraphics 链接与最小 IOKit ABI 声明；动态加载权限查询。 |
| 空值及接口缺失保护 | 避免不存在的电池数据构造字典导致崩溃；亮度函数不存在时不调用空指针。 |
| 悬浮窗启动结果 | 启动失败返回真实错误，不再仅凭 UI 开关报告成功；保留原有拖动、点击、自动隐藏。 |
| 剪贴板和网页错误桥接 | 在 MiniWatts 的内嵌页面恢复「复制数据」功能，网页脚本错误进入诊断日志。 |
| 主题偏好 | 修复 false 偏好被当作未设置的问题；显式浅色模式可以覆盖系统深色模式；浮窗保持透明背景，统计图坐标与图例使用 MiniWatts 主题文字颜色。 |
| 前后台切换 | 取消前台刷新任务时不再误报失联或尝试重启服务。 |
| 日志控制与隐私 | 应用和后台日志滚动限容；导出过滤常见标识，不记录浮窗检测到的其他应用名称；服务不可用时仍可导出应用诊断。 |
| 构建与发布 | 所有辅助程序从源码在 Actions 编译；IPA 不含签名、描述文件或生产测试样例；测试版标签映射为合法数字应用版本。 |

以上修正的静态、请求校验及编译检查不代表已验证真机特权控制。
